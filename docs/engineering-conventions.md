## 3. 模型接入

| 项 | 决定 |
|----|------|
| Agent 底座 | **`@earendil-works/pi-agent-core`**（ADR-006） |
| 模型调用层 | **`@earendil-works/pi-ai`**（ADR-004，不再自建 Provider） |

| API Key | 明文存 IndexedDB（见 ADR-005） |

**必须遵守**：

- 模型名、base URL、Key 全部走配置，**不硬编码在调用点**
- **只 import 用到的 provider 子路径**（@earendil-works/pi-ai/providers/deepseek），**绝不 import providers/all**（会把所有 SDK 打进包）
- Key 通过 **CredentialStore** 接口注入（我们用 IndexedDB 实现），不绕过它直接读写凭据表
- 新增供应商 = 注册一个新 provider，不改 pipeline
- ⚠️ **模型调用失败不抛异常**：必须检查 `res.stopReason === 'error'`，不能靠 try/catch（2026-10-03 实测发现）

## 4. 导入与解析

| 项 | 决定 |
|----|------|
| 编码 | **自动探测**；探测失败时给用户**下拉菜单手动选** |
| 分章失败 | 按 **4000 字**滑窗 + 模型判定边界 |
| 广告 / 作者的话 | **标记但不删**，在预览页高亮 |
| 超长章节 | 超过 **1 万字**切块（PRD 1.2） |

### 默认分章正则

```regex
(?:^|[^\w\n\r])([\s\u3000\uFEFF]*第\s*(?:[零一二三四五六七八九十百千万0-9]\s*)+[章回卷节部篇][^\n\r]{0,80})
```

> **实现时扩展了一处**：数字部分改为 `(?:[零一二三四五六七八九十百千万0-9]\s*)+`，
> 以匹配「第 十 二 章」这种字之间带空格的排版形态（原式匹配不了）。
> 该改动只放宽、不收紧，不影响原有形态。

**实现时必须注意三点**：

1. **必须加 `gm` 标志**（`g` 全局 + `m` 多行），否则只能匹配到第一个章节。
2. **捕获组现在包含标题**：已把原式的 `[^ \n\r]{0,80}` 改成 `[^\n\r]{0,80}`，这样 `第一章 标题` 这种带空格的写法能整行抓到。（原来的写法在第一个空格处就断了）
3. ⚠️ **`(?:^|[^\w\n\r])` 会消费掉章节标记前的一个字符**（为了兼容"，第一章"这类行内出现的情况）。用 `match.index` 切分时**必须补偿这个被吃掉的字符**，否则会把上一章末尾的标点切走。

→ 实现为函数 `splitChapters(text): Chapter[]`，Vitest 至少覆盖这些形态：
`第1章 x`、`第一章　全角空格`、`第一章 半角空格`、`第 十 二 章`、行内 `。第一章`、`Chapter 1`（不匹配 → 走滑窗兜底）。

## 5. 编译编排

| 项 | 决定 |
|----|------|
| 中途取消 | **支持**，**保留已完成章节** |
| 关闭标签页 | 中断；下次启动**从断点续跑**（P1 每章完成即落库） |
| 并发 | **可配，默认 3 路** |

**并发的副作用**：逐章落库的顺序会变乱。**不影响数据正确性**（每章都带章节号），但"进度显示"要用「已完成章节数 / 总章节数」，不能用"最后一个落库的章节"。

**加载流程**（TypeScript 负责）：

```

   ↓

   ↓

   ↓

```

**约定**：提示词是**独立的 .md 文件**，不硬编码在 TypeScript 里。改提示词不需要重编译。

## 7. TypeBox 与数据库的边界

**TypeBox = 业务数据 Schema 的唯一来源**（类型 / 校验 / 给模型的结构化输出）。

**数据库 Schema 仍然单独负责表结构和索引**（Dexie 的 `stores()` 声明），**不由 TypeBox 生成**。

> 有意的分离：业务数据的形状 与 存储的索引设计 是两个不同的问题，后者取决于查询模式。

**TypeBox 的导入路径**（0.34 版实测，容易踩）：

```ts
import { Type } from '@sinclair/typebox'                        // ✅ 根导出
import { TypeCompiler } from '@sinclair/typebox/compiler'       // ⚠️ 子路径，不在根导出
```

`TypeCompiler` 从根导出 import 会得到 `undefined`，运行时才炸。
**为什么是 TypeBox 而不是 Zod**：PI（`@earendil-works/pi-ai`）的 `Tool` 类型用 TypeBox。全项目统一到 TypeBox，就不用维护两套 schema 系统，也没有转换层。（ADR-003）

**必须做的防漂移措施**：

- 写测试：从 Dexie 的 store 定义取出字段名，与对应 TypeBox schema 的 properties 比对，**不一致就失败**
- 索引名与字段名统一在 `app/src/core/db/indexes.ts` 声明常量，两处引用同一份常量
## 8. 世界资产合并规则（P2 每 100 章 + P3 全书）

**两步：纯代码规则合并 → AI 字段级融合。** 参考 `lokenpee/WestWorld` 的实现。

### 第一步 · 本地规则合并（不调模型）

1. **名称归一化**：去掉版本 / 卷 / 章后缀
   - `_卷1`、`（卷二）`、`-第3章`、`_v2`、`_新版`、`_重做版`、`（修订版）`、`（备份）` 等
2. **比较用归一化**：转小写 + 去掉所有标点与空白
3. **判同**：
   - 归一化后相等 → 同一人
   - 或**互相包含**（`a.includes(b) || b.includes(a)`）→ 同一人
4. **并查集聚组**（UnionFind）：把两两判同的名字聚成一个合并组
5. **挑主名**：组内给每个名字打分，取最高者
   - 分数 = 内容长度 + 关键词数 × 20 − 50（带后缀惩罚）+ 5（可读性加分）

### 第二步 · AI 字段级融合

把同一实体的多个快照内容一起丢给模型，**强约束**：

1. 去重目标是**字段重复**，不是删减事实
2. 同字段同内容只保留一份
3. **同字段不同信息必须融合保留，不得覆盖或遗漏**
4. 禁止输出"字段补充1 / 补充2"这类键名，补充信息必须并入主字段
5. 同一字段有多条信息时写在同一个字段值内（用"；"分隔）
6. 尽量采用"字段: 值"的结构化格式
7. 不要输出解释文字

> 第 1–7 条取自参考实现的强制输出要求。

### 合并后的 ID 与引用回填

**ID 由代码决定，不由 LLM 决定**：

```
① 并查集聚组（两两判同）
② pickMainNameByQuality 挑主 → 保留主的原 ID（如 P001）
③ 被合并的实体不删除，写 { merged_into: "P001" }
④ 回填引用：nodes.characters / event_lines.characters / relationships 里的所有旧 ID → 主 ID
⑤ 融合内容：把被合并实体的独有字段并入主实体（这一步才用 AI）
```

**两个必须做到的**：

- **不删除**被合并的实体（加 `merged_into` 重定向）—— 可追溯、可撤销、防悬空引用
- **回填**所有引用 —— 否则节点/事件线里还指着旧 ID，数据就对不上了

`pickMainNameByQuality` 的打分：内容长度 + 关键词数 × 20 − 50（带后缀惩罚）+ 5（可读性加分）。
### ⚠️ P3 之后必须回填

P2 每 100 章已经合并过一轮，但 **P3 的全局合并可能把 P2 阶段分开的两个实体再合到一起**（跨窗口别名）。这时必须**回填**：把所有节点与事件线里指向被合并实体的引用，改成合并后的实体 id。

同时提供**手动归并**入口：用户在预览页可以把被拆开的两个实体合并。
