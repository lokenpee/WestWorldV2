# 用 React Flow + dagre 渲染事件网络，两级缩放（事件线级 → 节点级）

## Context and Problem Statement

用户要求把叙事资产**可视化呈现为事件网络**，"就像《底特律：变人》的事件脉络图"。

具体需求：

- **从左到右的树状图**，有分支与汇合
- **两级缩放**：默认显示事件线（粗），点开下钻到事件节点（细）
- 节点可点开看详情（含原文出处）
- **用户可编辑**（删除 / 修改事件线或节点）
- 后续要能**叠加玩家分支**（运行时 Agent 在地图上衍生新节点）
- 规模：一本长篇约 5,000–20,000 个事件节点、几百条事件线

## Decision

**用 `@xyflow/react`（React Flow）+ `@dagrejs/dagre` 布局。**

```
@xyflow/react      负责：节点/边渲染、平移缩放、框选、迷你地图、自定义节点
@dagrejs/dagre     负责：从左到右（LR）的分层布局计算
```

**两级缩放**：

| 层级 | 渲染什么 | 何时 |
|------|---------|------|
| **默认（事件线级）** | 一条事件线 = 一个节点 | 打开地图时 |
| **下钻（节点级）** | 该条线的事件节点展开成子图 | 双击某条线 |

**为什么不用力导向布局**：力导向适合"看聚类"，不适合"看流程"。《底特律》那张图是**有明确方向的时间流**，必须用分层布局（dagre / elk）。

**Non-goals**：

- 不做 3D / 不做动画特效
- 不做社区发现类的图分析可视化（那是 ADR-007 的图工具的事，不是 UI 的事）

## Consequences

- **好的**：React Flow 专为节点图设计，平移缩放/框选/自定义节点/迷你地图都是现成的，省掉大量交互代码。
- **好的**：`@dagrejs/dagre` 小巧成熟，"从左到右"是它的一等用法。
- **好的**：自定义节点就是普通 React 组件，事件线的样式（进度、状态、颜色）直接写 JSX。
- **坏的**：React Flow 在**数千节点**时会卡（DOM 渲染）。必须在两级缩放上做限制：默认只渲染事件线级（几百个节点），节点级一次只展开一条线。
- **坏的**：dagre 是**同步计算**的，大图布局会阻塞主线程。需要在计算前限制规模，或放进 Worker。
- **风险**：`@dagrejs/dagre` 已停止活跃维护（但成熟稳定）。若将来需要更强的分层能力（如交叉最小化、集群），可换 `elkjs`。

## Implementation Plan

- **Affected paths**：`app/src/features/network/`（地图 UI）、`app/src/features/network/layout.ts`（dagre 布局计算）、`app/src/features/network/nodes/`（自定义节点组件）、`app/src/core/graph/`（把 Dexie 数据转成 React Flow 的 `nodes`/`edges`）
- **Dependencies**：`@xyflow/react`、`@dagrejs/dagre`
- **Patterns to follow**：
  - 数据转换（Dexie → React Flow 的 nodes/edges）放在 `core/graph/`，UI 只消费结果（遵守 ADR-012）
  - 布局计算单独一个纯函数 `layoutNodes(nodes, edges): PositionedNode[]`，可单测
  - 节点级展开时**只渲染这条线的节点**，不渲染全图
  - 边的样式区分类型：`shares_node` / `shares_character` / `temporal_overlap`（PRD 1.5）
- **Patterns to avoid**：
  - ❌ 不要在 React 组件里直接读 Dexie（用 `useLiveQuery` 或 `core/` 暴露的函数）
  - ❌ 不要一次性渲染全部节点
  - ❌ 不要在 render 里算布局（布局结果要缓存）

### Verification

- [ ] 用一份 50 条事件线的样例数据，能渲染出从左到右、有分支的图
- [ ] 双击一条事件线能下钻到它的节点
- [ ] 拖动/缩放/框选正常；迷你地图可见
- [ ] 点一个节点能看到详情（含 `quote` 原文出处）
- [ ] 300 条事件线时交互不卡（事件线级）
- [ ] 全仓库搜索：`app/src/features/network/` 下不直接 import `@/core/db`

## Alternatives Considered

- **Cytoscape.js + dagre**：功能很强（图算法内置），但 API 偏命令式，与 React 状态同步要额外适配层。React Flow 更贴合 React。
- **D3 自绘**：最灵活，但平移缩放、框选、命中测试全要自己写，工作量不成比例。
- **sigma.js + graphology**：面向**力导向大图**（万级节点），但我们要的是**流程图**，方向不对；且它的渲染不是 DOM，自定义节点样式更难。
- **Mermaid / 静态图导出**：不可交互（不能点开节点、不能编辑），与需求冲突。

## More Information

**什么情况下该重新考虑**：

- 若事件线数量增长到 1,000+ 且卡顿 → 引入分层折叠（按时间区间/章节分页）
- 若需要更强的布局能力（集群、交叉最小化）→ 把 dagre 换成 `elkjs`
- 若布局计算成为瓶颈 → 把 `layoutNodes` 搬进 Web Worker（`core/` 是 DOM-free 的，搬迁成本低）
