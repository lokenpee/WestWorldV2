# 采用纯浏览器 SPA（React + TypeScript + Vite）作为运行形态

## Context and Problem Statement

产品定位是**个人自用的本地工具**，数据不出本机（PRD Q1）。技术形态需要同时满足：

- 需要 **IndexedDB**（结构化存储 + multiEntry 索引，见 PRD 2.11）
- 需要 **Blob 存储**（小说原文按章分片，几十 MB 级）
- 需要**长任务后台执行**（全书编译可能跑几十分钟，且要能断点续跑）
- 需要**复杂可视化**（底特律式从左到右流程图，两级缩放）
- 开发者是**一个人 + AI**，维护成本必须低

**用户明确的取向**：不引入桌面外壳，用 Web 技术栈直接跑。

## Decision

采用 **纯浏览器 SPA**：

```
React + TypeScript + Vite
       +
   Dexie + IndexedDB
```

**不使用 Tauri / Electron**，不起任何本地服务进程。

**Non-goals（明确不做）**：

- 不做桌面应用外壳（Tauri / Electron）
- 不做服务端 / 账号体系 / 云端同步
- 不做移动端

### ⚠️ 这个决定有一个必须管理的代价

浏览器存储**可能被清理或驱逐**（用户清理浏览数据、浏览器在磁盘压力下回收 storage）。对一个跑几十分钟编译才产出数据的工具，这等于**丢掉全部成果**。

**必须实现的四项缓解措施**（缺一项这个风险就没有被控制住）：

1. **请求持久化存储权限**：应用启动时调用 `navigator.storage.persist()`，并在被拒绝时明确提示用户
2. **全量导出 / 导入**：提供一键导出（JSON + 原文）与导入，让用户能自己备份
3. **启动时检测存储状态**：用 `navigator.storage.estimate()` 显示已用空间；未获得持久化权限时在界面上常驻提示
4. **文档化警告**：在 README / 首次运行引导里明确写出"不要用清理浏览器数据的方式清理本应用"

## Consequences

- **好的**：技术栈最简单，无需 Rust / Node 工具链，AI 生成代码的成功率最高。
- **好的**：开发调试成本最低（浏览器 DevTools 直接用），一个人 + AI 最容易推进。
- **好的**：React 生态能直接拿到 React Flow（地图渲染）与 shadcn/ui（界面）。
- **坏的**：**数据持久性弱于桌面应用**，必须靠上面四项缓解措施兜底。
- **坏的**：无法使用系统钥匙串，API Key 只能存在浏览器存储里（见 ADR-005，该 ADR 需重新决策）。
- **坏的**：长任务只能靠 Web Worker 在页面存活期间跑；用户关掉标签页就中断（缓解：逐章落库 + 断点续跑）。
- **坏的**：如果用户换了浏览器 / 换了 profile，数据不跟随（缓解：导出 / 导入）。

## Implementation Plan

- **Affected paths**：`app/`（新建工程根）、`app/vite.config.ts`、`app/package.json`、`app/src/main.tsx`、`app/src/features/storage/`（持久化权限与容量提示）
- **Dependencies**：`react`、`react-dom`、`typescript`、`vite`、`tailwindcss`、`shadcn/ui` 相关、`dexie`、`dexie-react-hooks`、`reactflow`、`zod`、`vitest`
- **Patterns to follow**：
  - 所有业务逻辑放 `app/src/core/`，**不依赖 React**，保证可单测
  - `app/src/features/` 只做 UI 与交互，通过 `app/src/core/` 暴露的函数读写数据
  - 需要长时间运行的任务放 `app/src/workers/`
  - 启动时在 `app/src/features/storage/` 里做一次持久化权限检查与提示
- **Patterns to avoid**：
  - ❌ 不要在 React 组件里直接调 IndexedDB
  - ❌ 不要把"持久化权限"做成一次性的、用户跳过就再也不提示的弹窗
  - ❌ 不要假设 localStorage 是可靠的（它更容易被清）

### Verification

- [ ] `pnpm dev` 能启动，`pnpm build` 能出产物
- [ ] 首次启动会请求 `navigator.storage.persist()`，被拒绝时有明确提示
- [ ] 能写入并读回一条 IndexedDB 记录，重启页面后数据仍在
- [ ] 导出得到一个 JSON + 原文文件；用一个全新浏览器 profile 能导入并完整还原
- [ ] 在 DevTools → Application 里能看到 IndexedDB 的实际占用大小
- [ ] 关闭标签页后重新打开，能从断点继续编译（配合 ADR-006 的长任务模型）

## Alternatives Considered

- **Tauri 2**：数据落在 `%APPDATA%`，不会被浏览器清理误删，安装包约 10 MB。**用户明确不采用**（不引入 Rust 工具链）。若将来数据丢失成为实际问题，这是首选的升级路径。
- **Electron**：纯 JS、生态成熟，但安装包约 150 MB，且仍要引入桌面外壳。**用户明确不采用**。
- **本地起 Node/Python 后端 + 浏览器前端**：多一个要管理的进程，违背"零配置"。

## More Information

**什么情况下该重新考虑**：

- 若实际使用中发生**数据被浏览器清理**的事故 → 升级到 Tauri（ADR-001 将被 supersede）
- 若编译任务的时长增长到"必须后台常驻"→ 纯浏览器无法满足，需桌面外壳
- 若需要系统钥匙串存 Key（ADR-005 的强安全方案）→ 必须换桌面外壳

相关：ADR-002（数据层）、ADR-005（密钥存储，因本决定需重新决策）、ADR-015（地图渲染）
